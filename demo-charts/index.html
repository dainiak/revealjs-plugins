RevealInteractiveCharts — scripted chart narration

Drive Vega-Lite and Plotly charts from reveal.js fragments — no in-chart clicks during the talk. Each slide exercises one feature.

Press Space / → to step through fragments. Esc for slide overview.

1. Inline spec — no external JSON file

<div data-vega> with no value picks up a child <script type="application/json" class="vega-spec">. The existing URL form (data-vega="img/foo.json") still works unchanged. 

<div data-vega style="height: 320px">
    <script type="application/json" class="vega-spec">
        {
            "$schema": ".../vega-lite/v6.json",
            "data": {"values": [
                {"month": "Jan", "sales": 120},
                ...
            ]},
            "mark": "bar",
            "encoding": {
                "x": {"field": "month", ...},
                "y": {"field": "sales", ...}
            }
        }
    </script>
</div>

2. Highlight one category at a time

A Vega-Lite param (an array of region names) drives the color/opacity encoding via a vega expression. Each click sets the signal to a different region — focus shifts, the rest dims. 

"params": [
    {"name": "active_regions", "value": []}
],
"encoding": {
  "color": {
    "field": "region", "type": "nominal",
    "legend": {
      "symbolOpacity": {"expr":
        "length(active_regions) == 0
         || indexof(active_regions, datum.value) >= 0
         ? 1 : 0.25"}
    }
  },
  "opacity": {
    "condition": {
      "test": "length(active_regions) == 0
               || indexof(active_regions,
                          datum.region) >= 0",
      "value": 1.0
    },
    "value": 0.25
  }
}

<script class="vega-fragments">
[
  {"at": 1, "signals": {"active_regions": ["North"]}},  # @1
  {"at": 2, "signals": {"active_regions": ["South"]}},  # @2
  {"at": 3, "signals": {"active_regions": ["East"]}},   # @3
  {"at": 4, "signals": {"active_regions": ["West"]}},   # @4
  {"at": 5, "signals": {"active_regions": []}}          # @5
]
</script>

The length(active_regions) == 0 guard means "empty list = highlight everything", which gives a clean baseline and a clean reset. Five clicks: N, S, E, W, all.

3. Cumulative subset — building up over clicks

Same recipe; the signal grows from [] → ["A"] → ["A","B"] → …, narrating "let's add the next one in." 

<script class="vega-fragments">
[
  {"at": 1, "signals": {"shown": ["A"]}},                  # @1
  {"at": 2, "signals": {"shown": ["A", "B"]}},             # @2
  {"at": 3, "signals": {"shown": ["A", "B", "C"]}},        # @3
  {"at": 4, "signals": {"shown": ["A", "B", "C", "D"]}},   # @4
  {"at": 5, "signals": {"shown":                           # @5
              ["A", "B", "C", "D", "E", "F"]}}             # @5
]
</script>

# State is cumulative: the merge logic re-applies all
# entries with at <= currentIndex on top of the
# baseline. Going backwards re-merges with smaller K.

4. Numeric signal — moving threshold

Any vega-lite param works, not just arrays. Here a numeric threshold drives both a colour split and a dashed reference line — both update on the same click. 

"params": [{"name": "threshold", "value": 0}],
"layer": [
  {"mark": "bar", "encoding": {
      "color": {"value": "#5b9bd5"},
      "opacity": {
        "condition": {
          "test": "datum.y >= threshold",
          "value": 1.0},
        "value": 0.25}}},
  {"mark": "rule", "encoding": {
      "y": {"datum": {"expr": "threshold"}}}}
]

<script class="vega-fragments">
[
  {"at": 1, "signals": {"threshold": 30}},  # @1
  {"at": 2, "signals": {"threshold": 50}},  # @2
  {"at": 3, "signals": {"threshold": 75}},  # @3
  {"at": 4, "signals": {"threshold": 0}}    # @4
]
</script>

5. Co-firing with bullets — same data-fragment-index

Each chart fragment is a real reveal.js fragment, so a chart-state change at step N fires together with any bullet whose data-fragment-index="N".

  • The Reason step is fast — pure LLM call.
  • Tool dominates: a 0.9s external HTTP call.
  • Observe is cheap — local parsing.
  • Answer goes back through the LLM.
  • All four together — the cost profile.

Five clicks. Each one shifts the chart's focus signal AND reveals one bullet — because they share the same data-fragment-index beat.

6. usermeta.revealFragments — fragments inside the spec

Vega-Lite's usermeta is "metadata the renderer ignores, available to the host app." Dropping the fragment list there keeps the chart self-contained — no sibling <script> tag, one JSON file. The plugin checks both places, so the two styles are interchangeable.

Six clicks: each brand spotlit in turn, then a final reset. The whole story lives in one JSON object — no sibling files, no synchronisation problems.

7. URL spec + Altair — single self-contained file

For real lectures the spec usually comes from Altair. With usermeta the fragment narration lives inside chart.save("img/foo.json")'s output, so the slide markup is just a single one-line <div>.

8. Plotly — same architecture, native API

Plotly works the same way as Vega: pre-injected proxies, cumulative-merge state, fragment list either in a sibling <script class="plotly-fragments"> or in usermeta.revealFragments. Entries use restyle / relayout instead of signals — same shape, just Plotly's native API.

Trace-level opacity (vs marker.opacity) dims the legend swatch too. restyle arrays are positional: index i → trace i. For layout-side gestures (annotations, axis ranges, shapes) use relayout with dotted-path keys like "shapes[0].y0".

9. Decoupled data — sidecar via container attribute

For one dataset, drop it into a separate JSON file and reference it via data-vega-data="...". The plugin fetches the file once, caches it, and writes spec.data.values at preInject time — so the inline spec stays slim enough to hand-edit (or paste into an LLM) while the bulky data lives next door. 

<div data-vega
     data-vega-data="data/quarterly-sales.json">
    <script type="application/json" class="vega-spec">
        {
          "data": {},
          "mark": "bar",
          "encoding": {
            "x": {"field": "quarter", ...},
            "y": {"field": "revenue", ...}
          }
        }
    </script>
</div>

# data/quarterly-sales.json (separate file):
# [{"quarter": "Q1 2023", "revenue": 142}, ...]

Vega-Lite's native {"data": {"url": "..."}} works too, with no plugin involvement — that's the right choice for vega-only decks. Use the data-*-data attribute when you want the plugin's per-URL fetch cache (one round-trip even if N charts share the dataset), or for Plotly where there's no built-in URL mechanism.

10. Multiple named datasets via sibling scripts

For multi-dataset specs (lookups, layered marks pulling from different sources), sibling <script class="vega-data" data-name="..." data-src="..."> blocks each populate one entry of spec.datasets. Inline JSON works too — useful when a small annotation dataset rides alongside a large time-series. 

<div data-vega>
  <script class="vega-spec">
    {"data": {"name": "trend"},
     "datasets": {"trend": [], "events": []},
     "layer": [
       {"mark": "line", "encoding": {...}},
       {"data": {"name": "events"},
        "mark": "rule", ...},
       {"data": {"name": "events"},
        "mark": "text", ...}
     ]}
  </script>

  <script class="vega-data"
          data-name="trend"
          data-src="data/trend.json"></script>

  <script class="vega-data" data-name="events">
    [{"day": "04", "label": "launch"},
     {"day": "09", "label": "fix"},
     {"day": "13", "label": "v2"}]
  </script>
</div>

Each named entry is written to spec.datasets[name]; the spec references them by {"data": {"name": "..."}}. URL entries hit the per-URL cache, so a dataset shared across multiple charts is fetched once. Plotly works the same way with plotly-data + a data-path writing into the spec.

11. The orthogonal story — chart-native interactivity

Slides 1–10 use fragment-driven scripted narration. But Vega-Lite already ships rich intrinsic interactivity — pan, zoom, hover, brush, legend filters. Drop a chart in via data-vega="path/to.json" and it works during the talk with the audience clicking the chart itself. The two styles compose: a chart can be both fragment-narrated and free-form interactive.

The next three slides load Altair-exported JSON files unchanged — no plugin-specific markup. The plugin just embeds them and gets out of the way.

Drag a brush rectangle on the left chart and/or click a legend entry on the right — the two views stay linked through Vega-Lite selections. Ideal for "let the audience explore" beats.
