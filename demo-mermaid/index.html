RevealMermaid plugin demo

Each slide exercises one feature.

Press Space / → to step through fragments. Esc for slide overview.

1. Inline :::fragidx-N — gradual reveal

Nodes appear in stages. Edges auto-propagate to max(srcFragidx, tgtFragidx).

2. Batch via class A,B,C fragidx-N

Same effect as inline :::, but compact for many nodes at the same step.

3. Subgraphs as fragment targets

Mermaid rejects ::: on subgraph lines — use a trailing class subgraphId fragidx-N.

4. Edge cases the resolver handles

Mermaid built-ins (__start__/__end__), underscored IDs, and self-loops all propagate fragidx correctly.

  • Step 1 — __start__ and agent appear. The arrow between them follows; the self-loop on agent too.
  • Step 2 — tool_node joins (note the underscored id parses correctly).
  • Step 3 — __end__ closes the graph.

5. %%! show X at N directive

Equivalent to :::fragidx-N, but reads as narration.

6. %%! highlight X at K — transient by default

Diagram is fully visible from slide load. at K with no modifier means "highlighted only on step K" — a moving spotlight via reveal.js's .current-fragment class. Use K+ for sticky-from, K- for sticky-to, K..M for a range, start for slide-load. The visual is a soft warm halo (drop-shadow glow) plus a small stroke-width bump — color-agnostic, so it remains visible regardless of the node's own fill.

Four highlights, four clicks. No trailing fade-out click — reveal.js's .current-fragment class drops automatically when the user clicks past, and the next directive's ON proxy triggers re-evaluation.

7. highlight A->B — edges

An edge target highlights both the arrow and its label as a unit. Use (arrow) or (label) to address them separately.

8. Multi-edge disambiguation

Two edges between the same pair? Use the source-side arrow form, a label match, or a numeric index.

9. dim and accent

dim reduces opacity; accent is a second highlight class with its own colour. Useful when contrasting two things on the same diagram at once.

at K — lit only at step K (transient, the new default). at K+ — sticky from K onward. at K- — on at slide load, fades after K. at K..M — range, inclusive both ends.

11. Co-firing with bullets — same data-fragment-index

A directive at step N is a real reveal.js fragment, so it fires together with any bullet whose data-fragment-index is also N.

  • The agent reasons about what to do.
  • It picks a tool and calls it.
  • It observes the tool's output.
  • It produces the final answer.

Each click reveals one node and one bullet together — they're both fragments at indices 1, 2, 3, 4.

12. Co-firing with code — diagram + highlight-ace

Mermaid directives and data-line-anchors share the same data-fragment-index space, so a node-highlight and a code-line highlight at step 3 fire on the same click.

13. Recolor per deck via CSS variables

This <section> overrides --fx-highlight-glow (green) and --fx-accent-glow (orange). The plugin's defaults defer to those variables, so the same directives produce different halo colours per deck.

14. Synthesis — narration with show + highlight + dim

Reveal nodes one by one, then call attention back to specific elements. The directive form reads almost word-for-word as the spoken narration.

  • User asks a question; we plan.
  • We search the web.
  • We score sources for trust.
  • We draft a summary.
  • We review and produce a final answer.
  • The scoring step is what protects us from low-quality sources.
  • The review step is the second line of defence.

15. Mindmap — directives by source label

Mindmap nodes have no source-level identifier in the SVG (mermaid emits opaque node_0, node_1…). Directives address them by the source token or the camelCased label; edges between named nodes (Frontend->React) work too.

Auto-edge-fragidx still applies: when Frontend appears at step 1, its incident edges (root→Frontend, Frontend→React, …) appear at step 1 too — without any edge directives.

16. Timeline — structural targets

Timeline SVGs have no source identifiers at all, so directives use synthetic structural targets — section:N / s:N, period:N / p:N, event:N / e:N — with optional slug forms (section:MainframeEra, event:VacuumTubes).

show on a section pulls in all its periods + connecting lines + events — the entire column appears at once. show on a period pulls in its events. The fx verbs (highlight/dim/accent) are intentionally narrow: they touch only the named element.

17. Gantt — task ids, sections, milestones

Gantt tasks expose source-level ids (a1, m1) on their rect, so directives address them directly. task:N indexes by source order; section:N cascades to all tasks in the section for show / fragment; milestone:N selects only milestone tasks.

Section show pulls in section bars + tasks + task labels — one click reveals the whole column. The fx verbs (highlight/dim/accent) act only on the named element, never on descendants.

18. Sankey — bare node names + flow indices

Sankey nodes have no source-level ids in the SVG (mermaid emits opaque node-1, node-2…). Directives address nodes by their source name directly; flows by index (flow:N) or by edge atom (Source->Target).

Sankey edges (g.link) have no auto-fragidx-propagation in this iteration — pair each show NodeName with explicit fragment flow:Ns for the incoming / outgoing flows you want to appear at the same step.

19. GitGraph — commits, branches, tags

Commits are addressed by index (commit:N) or by the user-given id (commit:init). Merges are commits too: merge:N selects only the Nth merge. Branches index from 1 (the implicit main is branch:1); tags accept the tag name directly.

Each commit:N resolves to the outer circle + (for merges) the inner commit-merge circle + the matching commit-label rect/text — the whole conceptual unit animates together. Connector arrows are addressable as arrow:N when you need them on a different step than their endpoints.

20. %%! spotlight X at K — inverted-dim model

spotlight is the strongest emphasis verb. The target gets an amber halo; every other first-class graphic in the same SVG fades to ~18% opacity via a :has()-driven CSS rule. Per-SVG scoped — multi-diagram slides aren't affected by each other.

Use sparingly — at most once or twice per deck. Overuse defeats the contrast (when everything is spotlit, nothing is). For an everyday "look here" cue, highlight is calmer.

21. Recoloured spotlight via CSS variables

Same as the previous slide, but this <section> overrides --fx-spotlight-glow (cyan halo) and --fx-spotlight-other-opacity (dim more aggressively to 12%).

What we did not show

  • %%% rules — the lower-level escape hatch for SVG-selector-based class assignment, attribute setting, and wrapper injection. Useful when mermaid syntax can't reach (e.g., sequence diagrams, attribute manipulation).
  • Math in node labels — write \(...\) or \[...\] inside any label and KaTeX renders it.
  • The verifier — node .claude/scripts/verify-mermaid-rules.js <file> --index=N validates fragidx propagation and flags would-be dangling arcs.
